# Часть 1. Архитектура и сети

## 1. Что вообще требуется построить

Представьте небольшой информационный сайт. Его содержимое — HTML-файл, который браузер получает по сети. Если единственная машина сломается, пользователь увидит ошибку. Поэтому в дипломе два одинаковых веб-сервера. Перед ними находится балансировщик: он выбирает, куда отправить очередной запрос, и проверяет работоспособность каждого сервера.

Но доступность — только одна обязанность администратора. Нужно заметить заполнение диска, найти причину ошибок и восстановить данные после потери машины. Поэтому вокруг сайта построены три системы: Zabbix для числовых метрик, Elasticsearch с Kibana для журналов и расписание снимков дисков для восстановления.

| Узел | Роль | Почему отдельная машина |
|---|---|---|
| diplom-web-a | nginx, первая копия сайта | Первый домен отказа |
| diplom-web-b | nginx, вторая копия сайта | Другая зона доступности |
| diplom-zabbix | Сервер мониторинга, БД и интерфейс | Наблюдает за остальными |
| diplom-elastic | Хранилище журналов | Изолировано от интернета |
| diplom-kibana | Поиск и визуализация журналов | Веб-интерфейс для оператора |
| diplom-bastion | SSH и запуск Ansible | Единственная точка административного входа |

> **Ключевая мысль.** Отказоустойчивость сайта и отказоустойчивость всех вспомогательных сервисов — разные задачи. В этом стенде сайт имеет две копии, Elasticsearch и Zabbix имеют по одному узлу.

### Вопросы на защите

**Почему не разместить всё на одной ВМ?** Общий отказ выключит одновременно сайт, мониторинг и журналы. Кроме того, диплом прямо требует отдельные машины для этих ролей.

**Что означает «зона доступности»?** Это отдельная инфраструктурная площадка облака. Размещение копий в разных зонах снижает зависимость от одной площадки, но не защищает от общей ошибки конфигурации обеих копий.

**Почему сайт статический?** Его легко синхронизировать: одинаковые файлы можно отправить на оба сервера. Приложению с пользовательскими загрузками потребовалось бы отдельное общее хранилище.

## 2. Частные и публичные IP-адреса

IP-адрес — числовой адрес сетевого интерфейса. Внутри стенда используются адреса `10.42.*.*`, которые относятся к частному диапазону. Интернет не маршрутизирует к ним пакеты напрямую. Публичный адрес выдаётся только тем узлам, с которыми должен общаться внешний пользователь или администратор.

VPC — логическая сеть проекта. Подсеть — её участок с собственным диапазоном адресов и привязкой к зоне. В Terraform созданы четыре подсети: публичные в зонах a и b, приватные в тех же зонах. Веб-серверы находятся в приватных подсетях; наличие слов «public» и «private» в имени не создаёт защиты автоматически. Защита возникает из сочетания отсутствия внешнего адреса, маршрутов и правил security groups.

DNS позволяет заменить числовой адрес именем. `diplom-web-a.ru-central1.internal` — внутреннее полное имя, или FQDN. Оно разрешается внутри облачной сети. На домашнем компьютере такое имя обычно не работает: домашний DNS не знает внутреннюю зону облака. Поэтому Ansible запускается на бастионе, который находится внутри VPC.

```bash
hostname
hostname -f
ip -br address
ip route
getent hosts diplom-web-a.ru-central1.internal
```

`hostname` показывает короткое имя машины. `-f` просит полное имя. `ip -br address` сокращённо выводит интерфейсы и адреса. `ip route` показывает маршруты: строка `default via ...` означает шлюз для неизвестных направлений. `getent hosts` проверяет разрешение имени тем же системным механизмом, которым пользуются обычные приложения. Если команда не вернула адрес, SSH по имени тоже не заработает.

### Вопросы на защите

**Почему inventory содержит имена, а не IP?** Это требование диплома и способ отвязать автоматизацию от назначенного числового адреса. Но имя должно разрешаться там, где запускается Ansible.

**Достаточно ли убрать внешний IP?** Для закрытия прямого входа из интернета — важный шаг, но внутренние соединения всё равно надо ограничивать security groups.

**Может ли приватная ВМ обновить пакеты?** Да, если у неё настроен исходящий маршрут через NAT.

## 3. NAT, бастион и security groups

NAT-шлюз нужен приватным ВМ для исходящих соединений: скачать пакет Ubuntu, Docker-образ или обновление Filebeat. Он подменяет частный адрес источника внешним. Ответ возвращается по уже созданному соединению. Это не делает ВМ доступной для произвольного входа из интернета.

Бастион решает другую задачу. Администратор соединяется с ним по SSH, затем обращается к внутренним машинам. На бастионе нет публичного веб-приложения. Здесь запускается Ansible. Для автоматизации создаётся отдельный ключ: закрытая часть остаётся на бастионе, открытая добавляется на управляемые машины.

Security group — набор разрешённых соединений на виртуальном сетевом интерфейсе. В стенде SSH к внутренним узлам разрешён с адреса бастиона; Zabbix agent принимает запросы с сервера мониторинга; Elasticsearch принимает HTTP только из внутренней сети. Публичный балансировщик принимает HTTP на 80. Kibana принимает соединения на 5601 через nginx с аутентификацией.

```bash
ssh ubuntu@PUBLIC_BASTION_IP
ssh ubuntu@diplom-web-a.ru-central1.internal
sudo ss -lntp
```

Первая команда выполняется на компьютере администратора. Вторая — на бастионе. `ss -lntp` показывает слушающие TCP-сокеты: `-l` только слушающие, `-n` без преобразования номеров в имена, `-t` TCP, `-p` процессы. `sudo` требуется для просмотра всех процессов.

При недоступности SSH сначала проверьте маршрут и правила, затем наличие слушающего процесса и только потом ключ. Таймаут соединения и `Permission denied (publickey)` — разные ошибки: при второй сервер уже ответил, значит проблема не в маршруте.

### Вопросы на защите

**Чем NAT отличается от бастиона?** NAT обеспечивает исходящий сетевой доступ; бастион обеспечивает контролируемый административный вход.

**Почему нельзя держать SSH открытым всему интернету?** Это увеличивает поверхность атаки. Ключи важны, но сетевое ограничение добавляет отдельный защитный слой.

**Как подключались при проблемах домашнего маршрута?** Через существующий сервер-посредник, который передавал SSH-трафик. Он не запускал сервисы диплома и не заменял ВМ Яндекс Облака.
