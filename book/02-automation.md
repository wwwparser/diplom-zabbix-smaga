# Часть 2. Terraform и Ansible

## 4. Зачем инфраструктура описана кодом

Можно создать шесть ВМ вручную в консоли, но тогда результат зависит от памяти администратора. В одной машине забудут группу безопасности, во второй окажется другая зона, в третьей — неправильный диск. Terraform хранит желаемую структуру в файлах `.tf`. Он обращается к API облака и создаёт ресурсы по этому описанию.

Terraform не устанавливает nginx внутри Ubuntu. Его область ответственности — сеть, ВМ, диски, балансировщик и расписание снимков. Ansible подключается к уже созданным машинам по SSH и настраивает ОС и приложения. Разделение помогает диагностировать ошибки: если ВМ не создана, проверяйте Terraform; если nginx не запущен на существующей ВМ, проверяйте Ansible и журнал службы.

| Файл | Назначение |
|---|---|
| `terraform/main.tf` | Все ресурсы Яндекс Облака |
| `.terraform.lock.hcl` | Зафиксированный провайдер |
| `.private/vars.json` | Значения облака, каталога и ключа оператора |
| `terraform.tfstate` | Связь кода с реальными ресурсами, не публикуется |
| `ansible/inventory.ini` | FQDN управляемых ВМ и группы |
| `ansible/site.yml` | Порядок настройки сервисов |
| `ansible/secrets.yml` | Пароли, исключены из Git |

> **Ключевая мысль.** Код описывает намерение, state описывает уже известное Terraform состояние. Потерять state — не то же самое, что удалить ВМ: ВМ останутся, но автоматизация перестанет знать, какими объектами она управляет.

### Вопросы на защите

**Почему не только Ansible?** Ansible тоже умеет работать с облачными API, но в этом проекте Terraform отвечает за зависимости и жизненный цикл облачных ресурсов, а Ansible — за конфигурацию внутри ВМ.

**Можно ли положить state на GitHub?** Нет. Он может содержать чувствительные данные и технические детали. В командной эксплуатации используется защищённый удалённый backend с блокировкой.

**Зачем lock-файл?** Чтобы следующая установка использовала ту же версию провайдера, а не случайно обновлённую.

## 5. Разбор Terraform по шагам

```powershell
yc iam create-token
$env:YC_TOKEN = yc iam create-token
terraform init
terraform fmt
terraform validate
terraform plan -var-file=../.private/vars.json -out=deploy.tfplan
terraform apply deploy.tfplan
terraform output -json
```

`yc` — CLI Яндекс Облака. `iam create-token` получает временный токен для API. Не публикуйте его вывод и не вставляйте токен в `main.tf`. В PowerShell запись в `$env:YC_TOKEN` устанавливает переменную только для текущего процесса и его потомков.

`init` скачивает провайдер — программу, которая переводит Terraform-ресурсы в вызовы API облака. В этом проекте основной реестр был недоступен, поэтому использовано зеркало Яндекс Облака. Это изменение способа доставки провайдера, а не замена самого облака.

`fmt` нормализует отступы. `validate` проверяет структуру конфигурации, но не гарантирует наличие квот или денег в облаке. `plan` вычисляет разницу между описанием и текущим состоянием. Сохранённый план позволяет применить именно рассмотренные действия. `apply` создаёт или меняет ресурсы; это команда с финансовыми последствиями. `output -json` возвращает адреса и идентификаторы для следующих этапов.

Ресурс `yandex_compute_instance.vm` использует `for_each`. Это означает: для каждой записи в словаре `local.machines` создать отдельную ВМ. Имя ключа — например, `web-a` — становится частью адреса ресурса в state. Если переименовать ключ, Terraform может увидеть удаление старого объекта и создание нового. Поэтому имена ключей не меняют без просмотра плана.

Ссылка `yandex_vpc_subnet.lab[each.value.subnet].id` задаёт зависимость. Terraform понимает: сначала создать подсеть, затем прикрепить к ней интерфейс. Не надо вручную расставлять паузы между созданием сети и ВМ.

### Вопросы на защите

**Чем plan отличается от apply?** Plan показывает предполагаемые изменения; apply выполняет их.

**Почему не выполнять apply сразу?** Сначала нужно увидеть, не предлагает ли Terraform заменить диск или удалить ресурс, который должен сохраниться.

**Что означает `~>` в ограничении версии?** Совместимый диапазон версий. Точный установленный выпуск закрепляется lock-файлом. Для строгого воспроизведения следите и за диапазоном, и за lock-файлом.

## 6. Разбор Ansible

Inventory группирует узлы по роли: `[web]`, `[elastic]`, `[zabbix]`, `[kibana]`, `[bastion]`. В строках стоят внутренние FQDN. На бастионе эти имена разрешаются через DNS облака. Параметр `ansible_user=ubuntu` задаёт пользователя SSH; `become: true` в playbook позволяет выполнять административные действия через sudo.

```bash
cd ~/diplom
ansible all -i ansible/inventory.ini -m ping
ansible-playbook -i ansible/inventory.ini ansible/site.yml --syntax-check
ansible-playbook -i ansible/inventory.ini ansible/site.yml
tail -n 40 ansible.log
```

`-i` выбирает inventory. Модуль `ping` в Ansible не посылает обычный ICMP echo: он проверяет SSH и возможность выполнить Python на удалённой машине. `--syntax-check` обнаружит ошибку YAML, но не проверит доступность Docker registry. Playbook выполняет задачи последовательно, а внутри каждой задачи обычно работает с несколькими машинами параллельно.

В отчёте `ok` означает, что желаемое состояние уже было достигнуто. `changed` — Ansible что-то изменил. `failed` — задача не выполнена. `unreachable` — к машине не удалось подключиться. Не называйте работу успешной, если в `PLAY RECAP` есть ненулевые `failed` или `unreachable`.

Большинство модулей Ansible идемпотентны: повторная задача `apt` не переустанавливает уже установленный пакет. В этой учебной версии задачи запуска контейнеров используют `docker rm` и `docker run`, поэтому повторный полный playbook перезапускает контейнеры. Данные БД сохранены в Docker volumes, но краткий перерыв возможен. В промышленной версии такие задачи следует заменить модулем управления контейнером или Compose с проверкой изменений.

### Вопросы на защите

**Что такое идемпотентность?** Повторное применение желаемой конфигурации не должно само по себе создавать новые изменения. Здесь это верно для файлов и пакетов, но не полностью для shell-задач запуска контейнеров.

**Почему `no_log: true`?** Чтобы пароль БД не появился в stdout Ansible. Это не заменяет исключение файла секретов из Git.

**Как исправлялась ошибка установки Zabbix agent?** В образе Ubuntu отсутствовал пакет в доступных репозиториях; подключён официальный репозиторий Zabbix, затем установлен агент.
